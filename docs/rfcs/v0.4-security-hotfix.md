# Lafetch v0.4 Security hotfix RFC

상태: 구현 완료

대상: `0.4.0-alpha.4`

## 목적

2026-08-09 보안 보고서에서 확인된 Medium 7건과 Low 2건을 공개 pre-release 전에 닫습니다. 개별 문자열만 차단하는 패치보다 origin, 요청 identity, 메모리 소유권과 leader/follower 전송 권한을 명시적인 불변식으로 고정합니다.

## Finding별 결정

| # | 심각도 | 문제 | Hotfix 계약 |
| ---: | --- | --- | --- |
| 1 | Medium | Dedupe leader의 Abort·Timeout 뒤 unsafe follower가 동일 쓰기를 재전송 | 자동 replacement leader는 Safe method에만 허용합니다. Unsafe method는 idempotency key가 있어도 모호한 leader 오류를 그대로 전파합니다. |
| 2 | Medium | 기본 Cache가 entry 수만 제한해 큰 Body 합계를 오래 보관 | `MemoryCacheStore`가 기본 500개와 64 MiB의 aggregate Body byte budget을 동시에 적용합니다. |
| 3 | Medium | 취소된 follower의 Promise reaction이 멈춘 leader에 남음 | 공유 Promise reaction 대신 취소 가능한 observer registry를 사용하고 follower signal이 끝나면 즉시 제거합니다. |
| 4 | Medium | `sig`, `signature`, `jwt`, `X-Amz-Signature`가 민감 이름 판정을 우회 | 중앙 민감 이름 matcher를 확장해 Cache·Dedupe를 우회하고 진단 snapshot을 redaction합니다. |
| 5 | Medium | 긴 TTL로 저장한 entry를 짧은 TTL reader가 재사용 | `CacheEntry.storedAt`을 보존하고 hit 수명을 `min(expiresAt, storedAt + reader TTL)`로 제한합니다. |
| 6 | Medium | `baseUrl` client의 cross-origin 입력이 공통 인증 설정을 상속 | resolved URL이 configured `baseUrl`과 다른 origin이면 Transport 전에 `HttpConfigurationError`로 거부합니다. |
| 7 | Medium | Cache·Dedupe identity가 Fetch 실행 정책 차이를 누락 | 사용자 key를 포함한 모든 key에 stable `Request` policy 필드를 추가합니다. |
| 8 | Low | 잘못된 URL이 deadline과 Abort listener를 만든 뒤 cleanup 경계 밖에서 실패 | URL·Query draft를 먼저 확정한 뒤 timer와 signal listener를 획득합니다. |
| 9 | Low | 진단 URL fragment가 그대로 남아 fragment 기반 secret을 보존 | URL resolution과 `RequestSnapshot`에서 fragment 전체를 제거합니다. |

## 불변식

### Origin

`baseUrl`은 단순한 문자열 결합 옵션이 아니라 client credential의 origin 경계입니다. 상대 URL과 same-origin absolute URL만 허용하며, 비교 가능한 origin이 없는 opaque base도 거부합니다. Cross-origin 호출은 공통 Header와 credentials를 공유하지 않는 별도 client를 사용합니다.

### Request identity

내장 key는 Method, URL과 Header를 유지합니다. 사용자 key는 Body나 tenant 등 호출자가 소유한 identity를 대체할 수 있지만 다음 Fetch 정책은 항상 Lafetch가 덧붙입니다.

```text
cache, credentials, integrity, keepalive, mode, priority,
redirect, referrer, referrerPolicy
```

민감 Header, URL·referrer user information, 민감 Query 또는 referrer fragment가 있으면 key 생성보다 먼저 Cache와 Dedupe를 우회합니다. HTTP 전송 identity가 아닌 요청 URL fragment는 Request를 만들기 전에 제거합니다.

### Cache memory와 freshness

Executor가 Body stream에서 실제로 받은 byte 수를 Cache finalizer에 전달합니다. `MemoryCacheStore`는 교체, 삭제, 만료 정리와 clear에서 같은 byte accounting을 사용합니다. Header와 객체 overhead는 byte budget에 포함하지 않으므로 entry-count limit을 함께 유지합니다.

외부 `CacheStore`도 `response`, `sizeBytes`, `storedAt`, `expiresAt`을 보존해야 합니다. 필드가 없거나 유효하지 않은 entry를 Core가 hit으로 사용하지 않습니다.

### Dedupe 전송 권한

Follower 취소는 leader와 다른 follower를 취소하지 않습니다. Safe method의 leader가 Abort·Timeout으로 끝난 경우에만 registry compare-and-replace로 replacement leader 하나를 선출합니다. Unsafe method는 origin이 요청을 처리했는지 알 수 없으므로 자동 takeover를 금지합니다.

## 호환성 영향

- `baseUrl` client에서 다른 origin의 absolute URL 또는 scheme-relative URL을 사용하던 코드는 origin별 client로 분리해야 합니다.
- Alpha `CacheStore` adapter는 필수 `storedAt`과 `sizeBytes`를 저장하고 반환해야 합니다.
- 사용자 Cache·Dedupe key의 실제 내부 표현이 Fetch policy를 포함하도록 바뀌므로 기존 외부 Cache entry는 miss가 될 수 있습니다.
- Unsafe Dedupe follower는 leader Abort·Timeout 뒤 자동 재전송하지 않고 오류를 받습니다.

아직 npm에 공개하지 않은 alpha 계약이므로 취약한 동작을 compatibility mode로 남기지 않습니다.

## 회귀 검증

각 finding은 수정 전 실패하는 회귀 테스트로 재현했습니다. Origin 우회, signed credential alias, 외부 Store key, Request policy identity, reader TTL, aggregate byte eviction, 초기화 cleanup, unsafe Abort·Timeout과 follower observer 분리를 정상·우회 대조군과 함께 검증합니다.

전체 gate는 다음 명령을 사용합니다.

```bash
pnpm typecheck
pnpm test
pnpm build
pnpm test:package
pnpm test:worker
pnpm test:next
pnpm test:browser
```

## Bundle 결정

실측 기준선과 hard ceiling은 다음과 같습니다.

| 대상 | 기준선 minified / gzip | Hard ceiling minified / gzip |
| --- | ---: | ---: |
| Complete root | `56,191 / 17,262 bytes` | `55 / 17 KiB` |
| 대표 JSON 요청 | `45,194 / 14,305 bytes` | `44.25 / 14 KiB` |
| Cache | `6,539 / 2,824 bytes` | `6.5 / 3 KiB` |
| Deduplication | `4,451 / 2,074 bytes` | `4.5 / 2.5 KiB` |

일반 요청의 gzip 14 KiB와 complete root gzip 17 KiB는 유지합니다. 증가분은 same-origin 검사와 buffered byte metadata, Cache accounting, 취소 가능한 Dedupe observer에 대응합니다. 선택 정책을 사용하지 않는 대표 graph에는 Cache·Deduplication 구현과 `MemoryCacheStore`가 계속 포함되지 않습니다.
