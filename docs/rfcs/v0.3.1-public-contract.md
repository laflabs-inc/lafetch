# v0.3.1 공개 계약 보강 RFC

상태: 구현 완료

## 목표

새 reliability policy를 추가하기 전에 첫 공개 버전에서 유지할 오류, Schema, native Fetch option과 요청 진단 계약을 확정합니다.

이번 단계는 다음 네 문제를 해결합니다.

1. `unknown` 오류를 package instance에 의존하지 않고 좁힐 방법이 없음
2. validator마다 별도 adapter가 필요한 비표준 Schema 계약
3. 일부 고급 `RequestInit`을 표현할 경로가 없음
4. 성공 `LResponse`가 native `Request`와 upload Body를 보존함

## RequestSnapshot

`LResponse.request`는 native `Request`가 아니라 다음 immutable snapshot입니다.

```ts
interface RequestSnapshot {
  readonly method: string;
  readonly url: string;
  readonly headers: Readonly<Record<string, string>>;
}
```

- upload Body와 native `Request` 참조를 보존하지 않습니다.
- URL user information, 인증 Header와 token 형태 Query는 제거합니다.
- snapshot과 내부 Header record는 모두 freeze합니다.
- 오류와 Telemetry도 같은 redaction 함수를 사용합니다.
- raw request가 필요한 Transport와 Feature hook는 실행 중에만 native `Request`를 받습니다.

`RequestSnapshot`은 진단 정보이며 재전송 입력이 아닙니다.

## Stable error guard

공개 오류 class는 기존처럼 유지하고 하나의 guard만 제공합니다.

```ts
try {
  await api.get("/users/1").timeout("1s");
} catch (error) {
  if (isHttpError(error, "ERR_HTTP_TIMEOUT")) {
    error.scope;
    error.timeoutMs;
  }
}
```

`isHttpError(error)`는 `HttpError`, code를 전달한 overload는 해당 subtype으로 좁힙니다.

| Code | Type |
| --- | --- |
| `ERR_HTTP_CONFIGURATION` | `HttpConfigurationError` |
| `ERR_HTTP_TRANSPORT` | `HttpTransportError` |
| `ERR_HTTP_ABORTED` | `HttpAbortError` |
| `ERR_HTTP_TIMEOUT` | `HttpTimeoutError` |
| `ERR_HTTP_STATUS` | `HttpStatusError` |
| `ERR_HTTP_DECODE` | `HttpDecodeError` |
| `ERR_HTTP_CONSUMPTION` | `HttpConsumptionError` |
| `ERR_HTTP_SCHEMA` | `HttpSchemaError` |
| `ERR_HTTP_FEATURE_CONFLICT` | `HttpFeatureConflictError` |
| `ERR_HTTP_FEATURE` | `HttpFeatureError` |
| `ERR_HTTP_NON_REPLAYABLE_BODY` | `HttpNonReplayableBodyError` |
| `ERR_HTTP_RESPONSE_TOO_LARGE` | `HttpResponseTooLargeError` |

guard는 `instanceof`만 사용하지 않습니다. `Symbol.for("@laflabs/lafetch/HttpError")` brand와 알려진 stable code를 함께 검사하므로 같은 runtime에 package가 중복 설치되어도 동작합니다. 구조만 비슷한 일반 객체, 알 수 없는 code와 예외를 발생시키는 Proxy는 거부합니다.

오류 class별 `isTimeoutError()` 같은 guard는 추가하지 않습니다.

## Standard Schema V1

`validate(schema)`는 dependency 없는 structural contract로 Standard Schema V1을 지원합니다.

```ts
const response = await api
  .get("/users/1")
  .validate(userSchema);
```

- `schema["~standard"].validate(value)`의 sync와 async 결과를 지원합니다.
- success의 `value`는 `LResponse.data`와 data mode의 직접 반환값이 됩니다.
- failure의 `issues`는 `HttpSchemaError.issues`에 보존합니다.
- validator가 throw하면 원래 오류를 `HttpSchemaError.cause`에 보존합니다.
- `~standard`, `parse`, `validate`를 함께 가진 Schema는 Standard Schema를 우선합니다.
- 기존 function, `parse`, `validate` adapter는 호환 경로로 유지합니다.

Lafetch는 Zod나 Valibot에 runtime dependency를 두지 않습니다. 실제 Zod와 Valibot은 개발 conformance test와 packed consumer에서만 사용합니다.

## Advanced RequestInit

드물게 필요한 stable Fetch option은 하나의 escape hatch로 전달합니다.

```ts
await api
  .get("/download")
  .requestInit({
    redirect: "manual",
    cache: "no-store",
    priority: "high",
  });
```

허용 필드:

- `cache`
- `integrity`
- `keepalive`
- `mode` (`navigate` 제외)
- `priority`
- `redirect`
- `referrer`
- `referrerPolicy`

다음 필드는 Lafetch의 기존 API가 단독 소유하므로 `requestInit()`에서 거부합니다.

| Fetch field | 공식 Lafetch 표현 |
| --- | --- |
| `method` | `get()`, `post()`, `request()` |
| `headers` | `header()`, `headers()` |
| `body` | `json()`, `body()`, `bodyFactory()` |
| `signal` | `signal()`과 Timeout lifecycle |
| `credentials` | `credentials()` |

알 수 없는 key와 value는 선언 시 `HttpConfigurationError`로 실패합니다. Request constructor가 런타임별 제약으로 거부한 조합도 Transport 오류가 아니라 `HttpConfigurationError`로 정규화합니다.

native `RequestInit.cache`와 Lafetch `.cache(ttl)`는 서로 다른 cache layer입니다. 두 계층이 조용히 중첩되면 `no-store`, revalidation과 application Cache 의미가 충돌하므로 함께 사용하지 못합니다.

모든 `RequestInit` 필드를 개별 fluent method로 복제하거나 일반 options object를 두 번째 요청 DSL로 추가하지 않습니다.

## 검증 계약

- TypeScript strict declaration
- error brand, stable code와 hostile unknown input
- native Body 미보존과 민감정보 redaction
- Standard Schema sync, async, success, issues와 cause
- Zod 4와 Valibot 1 actual consumer
- `requestInit()` snapshot, runtime whitelist와 cache 충돌
- Node.js, Chromium, Workers/Edge와 Next.js
- packed JavaScript·TypeScript consumer
