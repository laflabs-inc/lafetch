# Lafetch v0.3 API polish audit

상태: 구현 및 로컬 검증 완료 (`2026-07-26`)

대상: `0.3.0-alpha.0`

## 목적

새 DX utility를 추가하기 전에 공개 이름, 오류 경계, 응답 소비 문법, 내부 불필요 코드를 정리합니다. 아직 npm에 공개되지 않은 pre-release이므로 중복 호환 alias를 쌓지 않고 첫 공개 계약 자체를 단순하게 만듭니다.

## 공개 이름 규칙

| 이전 | 현재 | 판단 |
| --- | --- | --- |
| `LafetchClient` | `LClient` | Lafetch runtime object는 `L` 접두사 하나만 사용 |
| `RequestBuilder<T>` | `LRequest<T>` | 실제 사용자가 다루는 lazy request라는 역할을 노출 |
| `LafetchResponse<T>` | `LResponse<T>` | Buffered response envelope의 긴 브랜드 접두사 제거 |
| `LafetchStreamResponse` | `LStreamResponse` | live Response subtype 이름 단축 |
| `LafetchReadableStream<T>` | `LStream<T>` | native `ReadableStream`에 helper가 추가된 타입임을 표현 |

루트 factory의 고유 브랜드 타입 `Lafetch`는 유지합니다. `ClientOptions`, `RetryOptions`, `Transport`, `CacheStore` 같은 일반 계약은 브랜드 접두사를 붙이지 않고, 오류는 `Http*Error` 규칙을 유지합니다.

## 발견 및 처리

| ID | 심각도 | 발견 | 영향 | 처리 |
| --- | --- | --- | --- | --- |
| AP-01 | 높음 | 취소된 Deduplication leader를 여러 follower가 동시에 대체할 수 있음 | 동일 요청이 여러 번 Transport로 전달될 수 있음 | 현재 entry를 다시 확인하는 단일 replacement election 구현, 다중 follower 회귀 테스트 추가 |
| AP-02 | 높음 | JavaScript의 `validate(null)`이 falsy 검사 때문에 Schema를 조용히 건너뜀 | 런타임 검증을 요청했지만 검증되지 않은 데이터가 반환됨 | Schema를 선언 시점에 검사·snapshot하고 invalid value를 `HttpConfigurationError`로 거부 |
| AP-03 | 중간 | `retry({ statuses: "500" })`, `networkErrors: "yes"` 같은 값이 허용되거나 native `TypeError` 발생 | Retry 정책이 선언과 다르게 작동하고 오류 형식이 불안정함 | method, status, boolean, backoff duration을 선언 시점에 검증 |
| AP-04 | 중간 | 잘못된 timeout, signal, query, status matcher 등이 늦게 실패하거나 native `TypeError`로 노출됨 | Transport 호출 전 실패라는 계약은 지키지만 원인 위치와 오류 종류가 일관되지 않음 | 핵심 공개 입력을 선언 시점의 `HttpConfigurationError`로 정규화하고 duration은 한 번만 변환 |
| AP-05 | 중간 | Feature가 Buffered Body를 먼저 소비하면 `HttpTransportError`로 분류됨 | 전송 실패와 소비 소유권 위반을 구분할 수 없음 | `HttpConsumptionError`로 분류하고 회귀 테스트 추가 |
| AP-06 | 중간 | README가 direct `await`와 `as("json")`을 동급 문법처럼 제시 | 자동 decoder와 강제 decoder의 차이를 사용자가 추측해야 함 | direct `await`를 canonical 경로로 고정하고 비교표·잘못된 Content-Type 예제·IDE JSDoc 추가 |
| AP-07 | 낮음 | 내부 `dedupe()` wrapper, `defaultRuntime` export, `HttpError.meta`, 테스트 import가 사용되지 않음 | 공개·내부 표면과 유지 비용만 증가 | 제거하고 TypeScript unused/unreachable 검사를 상시 활성화 |
| AP-08 | 낮음 | Roadmap이 이미 통과한 v0.3 CI를 대기 상태로 표시 | 현재 프로젝트 상태를 잘못 전달 | Node.js, Chromium, Workers, Next.js 통합 완료 상태로 수정 |
| AP-09 | 높음 | direct `await`는 data만, `as("result")`만 envelope를 반환해 기본 요청이 HTTP 문맥을 잃음 | 상태·Header가 필요해진 순간 호출 문법을 바꿔야 함 | direct `await`를 `LResponse<T>`로 변경하고 중복 `result` mode를 공개 전 제거 |
| AP-10 | 중간 | 명시적 data mode도 `LResponse`를 반환하고 원본 접근이 `response.response`로 중첩됨 | `as(mode)`를 사용하고도 `.data`가 필요하며 기본 응답이 사용하지 않는 Body clone까지 보존 | data mode는 decoded value를 직접 반환하고 native 응답은 `as("response")`에서만 제공 |

## 자동 decoding과 강제 decoding

두 문법은 같은 기능의 장·단축형이 아닙니다.

```ts
const automatic = await api.get<User>("/users/123");
```

direct `await`는 `Content-Type`을 기준으로 JSON, text, bytes를 자동 선택하고 이를 `LResponse.data`에 담는 기본 경로입니다.

```ts
const forced = await api.get<User>("/legacy/users/123").as("json");
```

`as("json")`은 Header와 관계없이 JSON decoding을 강제하고 `T`를 직접 반환합니다. 서버가 JSON Body를 `text/plain`으로 잘못 표시하는 경우처럼 자동 판단을 의도적으로 재정의할 때만 사용합니다. 같은 규칙으로 `text`, `bytes`, `blob`, `formData` mode도 지정한 값을 직접 반환합니다.

`get<T>()`의 제네릭은 compile-time 타입 선언이며 런타임 검증이 아닙니다. 신뢰 경계에서 데이터 보장이 필요하면 `validate(schema)`를 함께 사용합니다.

## LResponse 호환성 경계

`LResponse<T>`는 `data`, `ok`, `status`, `statusText`, `headers`, `url`, `redirected`, `type`, `request`, `meta`를 제공합니다. 객체 자체는 shallow freeze하고 각 소비자에게 독립적인 `Headers`를 제공합니다. 디코딩된 기본 응답에는 native Body clone을 중복 보관하지 않습니다.

Body가 이미 디코딩된 envelope를 native `Response`의 subclass로 만들지는 않습니다. `text()`, `body`, `bodyUsed`, `clone()`의 의미가 실제 Body 소유권과 충돌하기 때문입니다. Buffered native escape hatch는 `as("response")`, live Body는 `as("stream")`으로 유지합니다.

## 제거 기준

- package root 또는 내부 실행에서 사용되지 않는 값은 제거합니다.
- 공개 전 이름 변경에 과거 alias를 추가하지 않습니다.
- Web Platform의 `Response`, `ReadableStream`, `pipeThrough()`, `getReader()`는 제거하지 않습니다.
- runtime validation은 실제 안전성·일관성 결함이 확인된 공개 입력에 집중하고 TypeScript 계약 전체를 중복 구현하지 않습니다.

## 검증

- TypeScript strict typecheck
- unused local·parameter, unreachable code, implicit return, switch fallthrough 검사
- 16 test files / 123 core tests
- 실제 npm tarball JavaScript·TypeScript 소비
- 자동 decoding과 강제 JSON decoding 차이
- 다중 Deduplication follower replacement 경쟁
- invalid JavaScript configuration의 declaration-time 오류
- Schema snapshot과 Buffered Body 소비 오류 분류
- 현재 브라우저 전체 공개 API: `41,484 bytes` minified / `12,879 bytes` gzip
- hard ceiling: `48 KiB` minified / `16 KiB` gzip
- Workers/Edge 격리 런타임
- Next.js App Router production build

실제 Chromium과 Node.js 20/22/24 matrix는 PR CI에서 다시 실행합니다.

## 다음 단계

이번 변경에는 새 convenience method를 넣지 않습니다. 정리된 `LClient`·`LRequest`·`LResponse`·`LStreamResponse` 계약을 먼저 병합한 뒤, DX utility는 사용 빈도·대체 가능한 Web API·번들 비용·오류 의미를 각각 검토해 작은 PR로 추가합니다.
